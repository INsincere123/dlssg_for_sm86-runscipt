# 使用个人配置启动鸣潮

默认源为本目录的 `Engine.ini`，由 `../../启动配置.ini` 的 `[鸣潮]` 分组指定。启动前关闭游戏与官方启动器，在“启动脚本”目录运行 `启动鸣潮.bat`；需要检查时运行 `启动鸣潮.bat -DryRun`，需要恢复全部部署时运行 `启动鸣潮.bat -RestoreDeployment`。

BAT 保留管理员提权与控制台关闭保护。脚本自动查找游戏 `Client/Saved` 中的画面配置目录；多个候选时，通过统一配置的“游戏配置目录”或 `-ConfigDirectory` 明确指定。

启动时按字节备份游戏原 `Engine.ini`，从个人明文源生成带标记的只读临时副本，再将游戏配置软链接到副本。个人源保持可编辑，游戏不能写回源文件。正常会话结束后恢复原件；鸣潮默认等待 10 秒热重启窗口，统一配置或 `-RestartGraceSeconds` 可调整。不要在游戏运行时中断脚本或同时启动多份部署。

只恢复画面配置可使用 `启动鸣潮.bat -RestoreEngineConfig`；完整恢复使用 `-RestoreDeployment`。遇到文件被替换、备份哈希不符或异常链接时保留现场，按日志处理，不删除部署记录绕过检查。详细行为以 [启动脚本说明](../../README.md) 为准。

`候选`、`基底`、`快照` 和 `备份` 保存个人实验及回退资料，`上游` 是独立 Git 子模块。上游更新不会自动改动个人 `Engine.ini`。本次只迁移目录，不调整引擎参数；原始说明与旧目录工作约定已归档。

测试候选时关闭游戏和启动器，等待恢复完成，再通过 `-EngineConfigSource` 传入候选文件完整路径。不要直接覆盖游戏原件。旧 `UserEngine.ini` 和历史 `-EngineIni=Engine.ini` 启动参数需检查冲突，不自动删除用户文件。

4K 输出、DLSS 档位、实际插帧倍率、画质和性能必须在游戏内验证；DryRun 或链接存在只证明对应检查范围。
