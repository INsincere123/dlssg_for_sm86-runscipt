# 启动脚本跨设备兼容性检查

检查日期：2026-10-17。检查对象为 `scripts` 下全部 9 个 PowerShell 实现、根目录三个 BAT，以及配置、恢复和迁移测试。

## 结论与证据范围

目标环境为 Windows 10 / Windows 11 **x64**、Windows PowerShell 5.1、具有管理员提权能力的常规桌面电脑。当前实际执行环境为 Windows 11 x64、Windows PowerShell 5.1.26100.9549。Windows 10 尚未实机运行，不能把当前系统上的测试称为 Windows 10 验收通过。

微软说明 Windows 客户端 10 及以后提供 [Windows PowerShell 5.1](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_windows_powershell_5.1)。脚本未使用 PowerShell 7 专有语法；不依赖手动安装 Python、Git 或第三方 PowerShell 模块运行启动流程。Git 只用于项目与上游子模块管理。

**脚本兼容性不等于 DLSSG 对所有 NVIDIA 显卡兼容。** 项目根说明当前标明运行组件面向 RTX 20（SM75）与 RTX 30（SM86）系列、Windows x64 / D3D12。显卡显示名称切换不改变实际硬件能力；不能根据伪装后的名称判断运行组件、INT8 超分或帧生成功能是否可用。其他 GPU 和驱动组合需要单独核实组件支持及游戏内运行证据。

## 各部分检查

| 部分 | 检查结果与限制 |
| --- | --- |
| 三个 BAT 与提权入口 | BAT 内容为 ASCII，路径从自身目录推导；共用入口使用系统 Windows PowerShell 和 conhost，参数通过 UTF-16 Base64 传递。已隔离验证 Unicode、空格和单引号；真实 UAC、交互窗口仍需两套系统现场验证。 |
| 控制台保护 | 保留 kernel32/user32 的传统控制台菜单接口及 Windows Terminal 转 conhost 逻辑。语法和 C# 编译在当前系统通过；关闭按钮保护与清理恢复需交互测试。Windows 11 的默认终端变化见[微软说明](https://support.microsoft.com/en-us/windows/apps/command-prompt-and-windows-powershell)。 |
| 统一配置 | 支持 UTF-8 有无 BOM、UTF-16/32 BOM、GBK 告警读取、CRLF/LF/CR。路径规范化与首次发现缓存已隔离测试；手填项优先，临时参数、DryRun 和恢复模式不写回。 |
| 游戏入口 | 两款实际脚本已在英文和中文迁移目录、不同用户目录、自动启动器位置、相对资源路径下完成隔离 DryRun。保留各自游戏结构和退出策略；游戏更新改变结构后需要重新定位。 |
| 日志 | 从项目目录定位 logs，无用户或盘符硬编码，保留超过一天普通日志的清理规则。项目必须允许写入日志、状态和需要缓存的配置。 |
| 资源部署和持久化恢复 | 使用 PowerShell 5.1 文件系统与 .NET 接口。现有隔离测试覆盖 intent/done、原件字节恢复、替换文件归档、只读清理、冲突保留和进程互斥。真实文件符号链接测试因未提权跳过；directory junction 与模拟链接通过。 |
| NVIDIA 识别 | 使用系统 [Get-PnpDevice -Class Display -PresentOnly](https://learn.microsoft.com/en-us/powershell/module/pnpdevice/get-pnpdevice)，按 VEN_10DE 识别，不依赖可修改的显示名称。唯一显卡自动选，多张必须明确指定，核显和非 NVIDIA 设备不会被误选。 |
| 显卡名称工具 | 已兼容普通文本及带 INF 前缀的名称；不认识的间接引用仍拒绝覆盖。备份明确按 Unicode/UTF-8 读取，驱动回退沿设备实际 Driver 引用定位，身份或原值变化时保留备份。相关写入测试均使用模拟注册表。 |

## 本轮修正

- 显卡状态文件原本 UTF-8 无 BOM 写入、系统默认编码读取；改为 .NET 明确读取，避免不同系统代码页损坏中文原始名称或目标名称。
- 支持普通设备名称字符串，同时保留间接名称前缀和异常格式保护。
- 原名称回退使用设备 Driver 属性中的完整类与实例索引，避免仅拼接固定类路径。
- 显卡工具自提权时使用系统 Windows PowerShell 完整路径，避免依赖 PATH 中的同名命令。

## 跨设备使用条件

- 搬迁后检查游戏目录，清空或改写旧设备缓存的启动器和游戏配置目录。缓存路径有效时不会主动搜索其他安装；不要携带旧设备的 `.state` 或 ProgramData 显卡备份作为新设备状态。
- 项目和游戏部署位置须允许写入，并支持符号链接、所需原子文件替换。常规本地 NTFS 是验收目标；不承诺 FAT/exFAT、只读介质、网络共享或受特殊策略限制的文件系统可完成部署。路径解析支持 UNC 不代表所有部署操作均可用于网络共享。
- 通过管理员 BAT 启动；[创建符号链接](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-createsymboliclinkw)受权限和系统策略约束。未提权的 DryRun 不能证明实际链接创建权限。
- 主仓库提供个人配置，上游子模块未初始化不影响个人默认源。源文件保持可编辑，运行时副本仍只读；不从上游说明推导或改变当前恢复约定。

## 可重复检查与剩余实机验收

在项目根目录运行 Windows PowerShell 5.1：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '启动脚本/tests/LauncherConfig.Tests.ps1'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '启动脚本/tests/DeploymentJournal.Tests.ps1'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '启动脚本/tests/Compatibility.Tests.ps1'
```

Compatibility.Tests 使用惰性占位 DLL/EXE，只执行 DryRun；这些占位文件不得用于正常启动。迁移场景运行于当前 OS，不模拟其他 Windows 内核或真实驱动。

Windows 10 与 Windows 11 各需补充一次：管理员 BAT/UAC、传统控制台及 Terminal、真实符号链接、实际游戏加载与配置应用、正常退出与强制中断后的恢复。NVIDIA 单卡与混合显卡电脑分别检查设备选择；多 NVIDIA 显卡场景手填后再验证。性能和稳定性需要独立的游戏采样，不由本报告推断。
