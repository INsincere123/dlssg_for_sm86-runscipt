# 鸣潮配置工作约定

## 作用范围与沟通

- 本文件适用于 `D:\Games\WuWa-Configs` 及其子目录，指导此电脑上的鸣潮配置分析、修改与验证。
- 默认使用简体中文，先说明结论，再说明依据、改动和验证限制。
- 用户要求“先分析”时只分析；授权修改后直接完成明确范围内的工作。
- 仓库配置、游戏正在使用的配置、启动脚本是不同来源，必须分别核实。
- 用户目标为 4K 输出、通过 `D:\Games\dlssg_for_sm86` 帧生成达到约 120 FPS 的显示流畅度，并兼顾画质。建议预设时必须结合实际插帧倍率、基础帧率和插帧开销，不能按原生 4K 120 FPS 的目标选档，也不能把插帧后的 120 FPS 等同于原生 120 FPS 的响应。

## 路径与仓库结构

- 配置仓库：`D:\Games\WuWa-Configs`。
- 鸣潮安装根目录：`C:\Games\Wuthering Waves\Wuthering Waves Game`。
- 游戏程序：`Client\Binaries\Win64\Client-Win64-Shipping.exe`，相对上述安装根目录。
- 游戏配置目录不写死。每次任务从安装根目录出发，结合当前仓库 README 的安装说明、实际目录结构和游戏生成的文件定位；游戏更新后必须重新核实，不能直接复用上次路径。
- 查找 `GameUserSettings.ini`、`Engine.ini` 等候选文件时，区分当前使用目录、旧版遗留目录、备份及启动脚本生成的临时目录；结合文件内容、更新时间、进程启动参数和可读日志判断，不能只取第一个搜索结果或仅按最新时间决定。证据不足时不要写入。
- 日志目录、游戏程序和旧配置路径也需随当前安装结构核实。发现 `UserEngine.ini` 等历史覆盖文件时仅先检查冲突，不应自动删除。
- 外部 DLSSG 工具目录：`D:\Games\dlssg_for_sm86`。需要分析帧生成或启动行为时读取当前脚本、配置及日志，不套用历史版本结论。
- 2026-10-10 核实鸣潮 `Run-WutheringWaves-DLSSG.ps1` 使用脚本内嵌配置生成临时 INI，再链接至游戏程序目录；修改工具根目录 `dlssg_sm86.ini` 不影响该脚本启动路径。当前脚本使用 `Optimized=1`、`MaxGeneratedFrames=3`、`Preset=Auto`、`Mode=Bundled`；其中 `MaxGeneratedFrames=3` 是最多生成三帧（最高 4X）的上限，不能据此断言实际倍率为 4X。后续重新读取脚本和最近运行日志核实。
- 仓库 `Config 1` 至 `Config 5` 各提供一个 `Engine.ini`；`Common` 提供可选 `DeviceProfiles.ini` 和 `Input.ini`；`RT Configs\README.md` 提供光追相关说明。
- 修改前阅读根目录 `README.md` 和目标 INI 的完整内容及注释；涉及光追再阅读 `RT Configs\README.md`。README 的显卡分档仅是参考，不能据此断言本机最佳档位或实测帧率。
- 本仓库提供配置文件和安装说明，没有自动定位、迁移或部署游戏配置目录的机制。上游可能更新 README 和配置，但不能假定每次鸣潮更新后都会及时同步；需要时核实上游提交与本地版本，保留本地修改后再按用户要求更新或部署。

## 配置修改原则

- 先检查 `git status --short` 和已有差异，保留用户改动；只修改本次任务涉及的文件，不擅自提交或推送。
- 默认在仓库中形成可审查的配置改动。用户要求安装或应用到游戏时，再备份并部署到已核实的游戏路径。
- 写入游戏配置前检查游戏是否运行、文件是否为符号链接或硬链接、是否有启动脚本动态生成或替换它；避免配置被退出保存覆盖或误改链接目标。
- 修改游戏现有文件前创建可恢复备份，并记录备份路径。不要把整个配置目录用仓库内容覆盖。
- 保持 INI 节名、语法、原有编码和注释习惯；检查同节重复键及跨文件覆盖关系，避免简单追加造成冲突。
- 每轮修改围绕具体目标，例如帧时间、画质、卡顿或输入延迟；目标不明确时先做只读分析，再询问关键偏好。
- 不能仅凭参数名称判断效果。涉及当前鸣潮版本支持的 CVar、DLSS、帧生成、光追或驱动功能时，优先检查本机文件和日志；必要时查证当前官方文档，并区分通用引擎说明与游戏实际实现。
- 分别判断 DLSS 超分辨率、游戏原生帧生成、外部 DLSSG 和驱动 Smooth Motion。设备名称伪装、菜单选项出现或 DLL 存在，都不能证明某条渲染路径实际工作。
- 按真实笔记本 GPU、4K 显示模式和 16GB 系统内存评估代价；不要默认扩大纹理池、缓存或提高光追质量，不承诺固定帧率提升。
- 默认不把 INI 设为只读。不顺带更改驱动、注册表、电源计划、DLL、启动脚本或删除缓存；这些操作须属于用户明确要求的任务范围。

## 验证与交付

- 静态检查确认差异范围、INI 节及键值、目标路径和备份；部署后核实落盘内容。
- 性能比较使用相同场景、路线、分辨率、画质、供电和热机条件；分别记录基础渲染帧率与插帧后显示帧率，条件允许时记录帧时间、1% Low、CPU/GPU 负载及内存占用。
- 检查画面闪烁、拖影、纹理加载、阴影、反射和输入延迟；没有实测就明确写“待游戏内验证”。
- 不能把文件写入成功、参数存在或脚本检查通过描述为游戏优化已生效。日志若无法直接解码，说明限制，不据此推断运行结果。
- 交付时简述修改内容、理由、验证结果和恢复方法；尚未测试的性能或视觉效果单独说明。
- Windows PowerShell 读取中文前使用 `chcp 65001`；路径含空格时使用可靠引用，文件操作优先使用 `-LiteralPath`，搜索优先使用 `rg`。
