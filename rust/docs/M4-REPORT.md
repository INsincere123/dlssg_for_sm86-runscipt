# M4 界面验收报告

测量日期：2026-11-22～23（Asia/Shanghai）  
环境：Windows 11 26300 x64 · RTX 3080 Ti Laptop · 系统缩放 **150%** · release 构建（`opt-level="s"` + LTO）
工具：`rust/tools/measure-ui.ps1`（构建 → 启动 → 稳定后采样 → 截图）

## 1. 结论

| 指标 | 目标 | 实测 | 结论 |
|---|---|---|---|
| 常驻内存（生产模式，窗口常驻） | ≤85 MB | **84.3 MB**（三次 84.2 / 84.3 / 84.3） | 达标 |
| 常驻内存（自检模式，强制每 100 ms 重绘） | — | **87.0 MB**（三次 87.0 / 87.0 / 87.1） | 仅测量用，不作产品指标 |
| 首帧耗时 | ≤300 ms | **128–161 ms**（多次 3 连测：平均 136 ms、峰值 161 ms） | 达标 |
| DPI 缩放 | 150% 不缩放错 | `pixels_per_point = 1.5`，中文正常 | 达标 |
| 无控制台窗口 | 必须 | `console_window = 0`（M2 已验） | 达标 |
| 单实例 | 第二个不开窗 | 第二个实例 **64 ms** 内退出，exit 0 | 达标 |

## 2. 测量方法

1. `cargo build --release -p launcher`
2. 每次启动 `DlssgLauncher --ui-selftest 2200 <report>`（或生产模式直接启动），**等待 ≥1000 ms 后采样**
3. 采样 `WorkingSet64` 与 `PrivateMemorySize64`；从报告里取 `first_frame_ms` 与 `pixels_per_point`
4. 第一次运行额外按窗口矩形截图，用于人工核对中文与布局

**采样延迟很关键**：字体（微软雅黑 ttc）与 GL 初始化期间有明显临时峰值——700 ms 时读到 142 MB，900 ms 后稳定在 84 MB。任何低于 900 ms 的读数都不代表常驻内存。

## 3. 截图

`rust/docs/m4-ui-150.png`（915×617，150% 缩放下的窗口截取）：中文标题、两个游戏行、状态胶囊（可启动 / 需定位）、UE5 标记、目录路径均正常渲染。

已知不足：该图按 `GetWindowRect` 取矩形，在 150% 缩放下只截到窗口左上部分，**底部操作栏未入画**；布局本身没有重叠（同一窗口用 `EnumWindows` 找到的可见区域完整）。缩放下更准确的取图方式应改用 `DwmGetWindowAttribute(EXTENDED_FRAME_BOUNDS)`，留待 M4 之后按需修正。

## 4. 本轮修掉的问题

1. **自检窗口可能永不退出**：`--ui-selftest` 依赖 `ui()` 被反复调用，窗口失焦/被遮挡时 egui 会停止重绘，`close_at` 永远不到期（实测挂起过一次）。已在自检模式下加 `request_repaint_after(100 ms)`，修复后 15 秒内必定退出。
2. **误判"启动即退出"**：连续启动时若上一个实例还在，第二个会按单实例设计立刻退出（exit 0、无窗口、WS=0），不是故障。测量脚本因此需要在两次运行之间确认前一个进程已结束。
