# M4 界面验收报告

测量日期：2026-11-22～23（Asia/Shanghai）  
环境：Windows 11 26300 x64 · RTX 3080 Ti Laptop · 系统缩放 **150%** · release 构建（`opt-level="s"` + LTO）
工具：`rust/tools/measure-ui.ps1`（构建 → 启动 → 稳定后采样 → 截图）

## 1. 结论

| 指标 | 目标 | 实测 | 结论 |
|---|---|---|---|
| 常驻内存（生产模式，窗口常驻） | ≤85 MB | **84.3 MB**（三次 84.2 / 84.3 / 84.3） | 达标 |
| 常驻内存（自检模式，强制每 100 ms 重绘） | — | **87.0 MB**（三次 87.0 / 87.0 / 87.1） | 仅测量用，不作产品指标 |
| 首帧耗时 | ≤300 ms | **128–161 ms**（多次 3 连测：平均 136 ms、峰值 161 ms） | 达标 |
| DPI 缩放 | 150% 不缩放错 | `pixels_per_point = 1.5`，中文正常 | 达标 |
| 无控制台窗口 | 必须 | `console_window = 0`（M2 已验） | 达标 |
| 单实例 | 第二个不开窗 | 第二个实例 **64 ms** 内退出，exit 0 | 达标 |

## 2. 测量方法

1. `cargo build --release -p launcher`
2. 每次启动 `DlssgLauncher --ui-selftest 2200 <report>`（或生产模式直接启动），**等待 ≥1000 ms 后采样**
3. 采样 `WorkingSet64` 与 `PrivateMemorySize64`；从报告里取 `first_frame_ms` 与 `pixels_per_point`
4. 第一次运行额外按窗口矩形截图，用于人工核对中文与布局

**采样延迟很关键**：字体（微软雅黑 ttc）与 GL 初始化期间有明显临时峰值——700 ms 时读到 142 MB，900 ms 后稳定在 84 MB。任何低于 900 ms 的读数都不代表常驻内存。

## 3. 截图

`rust/docs/m4-ui-150.png`（915×617，150% 缩放下的窗口截取）：中文标题、两个游戏行、状态胶囊（可启动 / 需定位）、UE5 标记、目录路径均正常渲染。

已知不足：该图按 `GetWindowRect` 取矩形，在 150% 缩放下只截到窗口左上部分，**底部操作栏未入画**；布局本身没有重叠（同一窗口用 `EnumWindows` 找到的可见区域完整）。缩放下更准确的取图方式应改用 `DwmGetWindowAttribute(EXTENDED_FRAME_BOUNDS)`，留待 M4 之后按需修正。

## 4. 本轮修掉的问题

1. **自检窗口可能永不退出**：`--ui-selftest` 依赖 `ui()` 被反复调用，窗口失焦/被遮挡时 egui 会停止重绘，`close_at` 永远不到期（实测挂起过一次）。已在自检模式下加 `request_repaint_after(100 ms)`，修复后 15 秒内必定退出。
2. **误判"启动即退出"**：连续启动时若上一个实例还在，第二个会按单实例设计立刻退出（exit 0、无窗口、WS=0），不是故障。测量脚本因此需要在两次运行之间确认前一个进程已结束。

## 5. 未覆盖

- 手工交互：设置页保存后重开、添加游戏的真实扫描、日志目录打开的资源管理器目视确认——均未做人工点击验证。
- 多显示器与 100% / 200% 缩放未测；只测了本机的 150%。
- 空闲 CPU 占用未测（egui 默认按需重绘，预期接近 0，但无数据）。

## 6. 后续复查：字体内存映射（2026-11-24）

**改动**：旧做法用 `std::fs::read` 把 `%WINDIR%\Fonts\msyh.ttc`（19,704,352 B = 18.8 MB）整块读进堆，
`epaint::FontData` 又一直持有这份字节，等于界面进程常驻 18.8 MB 专用内存只为"放着字体文件"。
现改为只读内存映射（`CreateFileMappingW` + `MapViewOfFile`，`PAGE_READONLY` / `FILE_MAP_READ`），
再用 `epaint::FontData::from_blob` 直接引用映射区（epaint 0.37 明确支持"内存映射的系统字体、不复制"），
映射失败（字体缺失、无权限、空文件、映射失败）仍回退 `fs::read`，行为与旧版一致。
实现：`launcher-win/src/fontmap.rs`，接入点 `launcher/src/ui.rs` 的 `font_data()`。

**同会话 A/B**（同一台机器、同一个空偏好目录、旧构建 = `dist/DlssgLauncher-v0.1-full/DlssgLauncher.exe`
（`cb230f3`，`fs::read`）；各跑 3 次 `--ui-selftest 4000`，1.2 s 起每 0.8 s 采样一次）：

| 构建 | 总工作集 | 专用工作集（任务管理器「内存」） | 私有提交 | 线程 / 句柄 |
|---|---|---|---|---|
| 旧（`fs::read`） | 88.5 MB | 55.6–58.8 MB（平均 57.7） | 98.0 MB | 14 / 336–342 |
| 新（内存映射） | **70.0 MB** | **36.8–40.1 MB（平均 38.8）** | **79.6 MB** | 14 / 338–344 |

- 三档一起少了 **18.4–18.9 MB**，与字体文件大小（18.8 MB）吻合；句柄多 2 个（文件 + 映射）。
- 映射区是文件页：不计入专用提交，内存吃紧时系统可直接回收，同名字体被其他进程映射时还能共享物理页；
  只有真正光栅化用到的字形才换入，冷启动也省掉一次 18.8 MB 整读。
- 既有验收工具 `tools/measure-ui.ps1`（1 s 采样、3 次）在同一构建上读到总工作集
  **69.6 / 69.8 / 69.6 MB**，私有提交 79.4–81.2 MB，`pixels_per_point = 1.5`，中文渲染正常。
  §1 里旧构建的 84.3 MB 是 2026-11-22 另一次会话（偏好与驱动状态不同）记录，
  精确的前后差以上表同会话 A/B 为准。

**未覆盖**：没有 `msyh.ttc` 的机器（回退整读，内存回到旧值）未实测；`msyhl` / 字体子集等进一步压缩没做；
映射对首次字形光栅化的耗时影响没有单独计时（`--ui-selftest` 报告现在只写 `ui` / `pixels_per_point` /
`games` / `tray`，已不再有 `first_frame_ms`，所以本节没有首帧前后对照）。
